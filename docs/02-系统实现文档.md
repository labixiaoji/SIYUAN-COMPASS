# 系统实现文档

本文档描述当前代码实现。产品规则以 01-问卷与报告规范为准，数据处理以 04-数据隐私与保留策略为准，部署操作以 03-部署与运维文档为准。

## 1. 技术结构

~~~text

  -> 生产环境由 Nginx 代理 /api
  -> FastAPI

## 2. 账号与权限

当前后端提供本地账号注册、登录、改密和当前用户接口。密码使用 PBKDF2-SHA256，登录 token 使用 HMAC 签名。

- 学生只能读取自己的任务、报告和反馈。
- 学生只能删除自己的报告或全部业务数据。
- 管理员可以查看学生填写记录、已生成报告、失败诊断和报告修改记录，并编辑报告。
- 真实 jAccount 接入不在本轮实现范围，由学校侧负责。

## 3. 报告生成

报告使用持久化任务流程：

1. POST /api/assessment-jobs 校验问卷、检查账号并检查每日配额。
2. 任务及临时输入写入 PostgreSQL。
3. 后台任务领取租约并定时心跳。
4. 画像阶段调用当前模型并校验结构。
5. 报告阶段生成六模块 Markdown 并执行质量检查。
6. 保存问卷、画像、报告和报告版本；只有成功任务才清除临时输入和关联云端草稿。
7. 前端通过 GET /api/assessment-jobs/{jobId} 轮询进度。

任务状态包括 queued、running、success、failed 和 cancelled。失败或取消任务保留脱敏问卷快照，学生可通过失败记录恢复问卷后重新提交；成功任务会在终态事务中清除 input_data 和 source_job_id 对应的云端草稿。服务重启时会恢复可恢复任务；租约、claim token 和条件更新用于避免重复执行。每日生成配额默认关闭，设置正数后按账号限制创建次数；终态任务默认保留 30 天。

失败任务会在 generation_jobs.data 中保存最新一次结构化错误，包括错误代码、失败阶段、可重试标记、供应商状态码和追踪编号。前端管理员只看到脱敏诊断摘要，完整请求、响应和堆栈不进入业务数据库。

画像和报告的模型输入均经过同一套最小必要字段过滤：直接身份信息、内部元数据、收入和不参与分析的字段不会发送；空的可选答案也不会占用提示词空间，模型按“未出现即未提供”处理。画像阶段只传入本次有答案的题目规则及相关交叉字段；报告阶段以结构化画像为主，只补充困惑、基本信息和 5—10 年愿景等必要问卷字段，避免同一答案同时以长文本和格式化 JSON 重复出现。当前提示词版本分别为 `profile-analysis-v1.8.0` 和 `career-blueprint-v1.2.0`。

## 4. 数据库

数据库由后端启动时创建表，目前没有 Alembic 迁移。

| 表 | 用途 |
| --- | --- |
| users | 学生和管理员账号、每日报告生成配额 |
| assessment_responses | 问卷主记录和 JSONB 答案 |
| assessment_scores | 能力与兴趣分数 |
| assessment_choices | 多选答案拆行记录 |
| assessment_drafts | 每个账号一份云端草稿，并记录可选的 source_job_id 关联任务 |
| career_profiles | 结构化用户画像 |
| reports | 当前报告 |
| report_versions | 报告生成和人工编辑历史 |
| generation_jobs | 任务状态、租约、脱敏临时输入和结构化失败信息 |
| report_feedback | 报告评分和反馈 |
| admin_audit_logs | 管理员敏感操作记录 |

业务记录通过 user_id、response_id、profile_id 等关联字段连接，复杂对象使用 JSONB 保存。问卷删除、报告删除和全部业务数据清除在数据库事务中执行。

POST /api/auth/register
POST /api/auth/login
GET  /api/auth/me

~~~

### 5.2 问卷和任务

~~~text
GET    /api/assessment-draft
PUT    /api/assessment-draft
DELETE /api/assessment-draft
POST   /api/assessment-jobs
GET    /api/assessment-jobs/{jobId}
GET    /api/assessment-jobs/{jobId}/draft
POST   /api/assessment-jobs/{jobId}/cancel
POST   /api/assessments
~~~

PUT 草稿使用版本号进行乐观并发控制；版本冲突返回 409。POST /api/assessments 保留兼容旧调用，但同样先写入队列并等待任务完成，不能绕过并发限制。

### 5.3 报告、反馈和隐私

~~~text
GET    /api/reports

GET    /api/reports/{reportId}
DELETE /api/reports/{reportId}
POST   /api/reports/{reportId}/feedback
DELETE /api/privacy/my-data
~~~

### 5.4 管理员和模型

~~~text
GET /api/admin/metrics
GET /api/admin/records
GET /api/admin/assessments
GET /api/admin/assessments/{responseId}
GET /api/admin/generation-jobs
GET /api/admin/generation-jobs/{jobId}
GET /api/admin/generation-jobs/{jobId}/draft
GET /api/admin/audit-logs
PUT /api/admin/reports/{reportId}
GET /api/llm/status
~~~

管理员前端只有两个主要业务入口：`/admin/assessments` 填写记录和 `/admin/reports` 已生成报告。填写记录同时展示问卷提交、排队/生成阶段、进度、失败信息和可恢复草稿；生成任务列表不再作为独立页面，旧的 `/admin/generation-jobs` 地址会跳转到填写记录，任务详情和失败草稿仍可通过记录中的深链打开。已生成报告只返回成功保存的报告，并使用与旧版一致的宽版卡片展示学生、问卷、报告状态和反馈，支持按姓名、学院、专业模糊搜索以及按报告状态和年级筛选。

`/admin/audit-logs` 仅返回报告修改或删除记录。管理员查看总览、填写记录、问卷、任务、草稿、报告和日志本身不会写入审计日志；报告编辑由 `PUT /api/admin/reports/{reportId}` 记录修改字段、质量状态和字数等必要元数据，不保存完整修改前后正文。

问卷草稿同时使用云端草稿和本地草稿。云端草稿按登录账号隔离，本地草稿使用带用户标识的存储键并设置过期时间。退出或 401 时清理当前账号草稿。

## 7. 报告生成队列

问卷提交后先在 PostgreSQL 的 `generation_jobs` 中创建 `queued` 任务，由固定数量的后台 Worker 按 `created_at, job_id` 顺序使用 `FOR UPDATE SKIP LOCKED` 原子领取。默认启动 3 个 Worker；服务重启时未完成任务依靠租约自动恢复，优雅停止会释放当前领取并重新排队。

画像、报告和质量修复等所有模型请求都经过统一模型接口的进程内信号量，默认最多同时 3 个请求。`LLM_MAX_REQUESTS_PER_MINUTE` 按请求启动时间平滑限制速率，默认每分钟 8 次，画像、报告、质量修复和重试请求共用名额；设置为 0 可关闭。每次请求的输出上限由 `LLM_MAX_OUTPUT_TOKENS` 控制，默认 10000；它只影响 `max_tokens`，不改变供应商模型的上下文窗口。网络断开、超时、429 和 5xx 最多重试 2 次，等待退避时释放模型名额；鉴权、权限和参数错误不重试。任务会记录 Worker 尝试次数、模型请求次数、网络重试次数和质量修复次数。

Worker 开始调用模型前再次检查原始问卷快照。缺失字段会以 `ASSESSMENT_INCOMPLETE` 失败并列出字段名，不会用模型默认值补齐。任务绑定的关系型 `user_id` 是唯一归属依据，恢复 JSON 中的 `userId` 不参与授权或写入。

任务会保存 response、profile、report 检查点。已有且归属一致的画像或报告可以直接续跑或修正状态；失败、取消和服务重启保留问卷恢复数据，只有报告成功保存后才清除任务输入和对应云端草稿。

管理员可查看排队、运行、成功、失败和取消数量，以及脱敏后的失败阶段、错误代码、供应商状态码、追踪编号和重试统计；不返回模型密钥、完整请求或完整响应。

## 8. 当前边界

- 没有真实 jAccount 集成。
- 队列和租约持久化在 PostgreSQL，Worker 仍在单个 FastAPI 进程内；当前部署只运行一个后端进程，跨多服务器时需要将进程内模型信号量升级为数据库全局名额。
- 数据表由应用启动时创建，没有正式迁移工具。
- 生产 Compose 只提供 HTTP，正式上线应放在 HTTPS 反向代理之后。
- 前端报告使用定制 Markdown 渲染器，不是完整 Markdown 解析器。

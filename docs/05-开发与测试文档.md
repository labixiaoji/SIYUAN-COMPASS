# 开发与测试文档

## 1. 开发环境

项目需要：

- Python 3.12 或兼容版本
- Node.js 22
- PostgreSQL 16，或使用开发 Compose 启动
- Docker Desktop（如果使用 Docker 开发）

首次配置：

~~~bash
cp .env.example .env
~~~

不要把真实 API Key、数据库密码和 AUTH_SECRET 写入代码或提交到 Git。

## 2. 直接运行

后端：

~~~bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
~~~

前端：

~~~bash
cd frontend
npm install
npm run dev
~~~

直接运行后端时需要可访问的 PostgreSQL。也可以使用 docker-compose.dev.yml 同时启动数据库、后端和前端。

## 3. 测试命令

后端：

~~~bash
cd backend
python -m unittest discover -s tests
~~~

前端：

~~~bash
cd frontend
npm test
npm run typecheck
npm run build
~~~

测试重点包括问卷校验、草稿隔离和冲突、失败任务快照恢复、固定 Worker 队列、FIFO 原子领取、任务错误代码、任务租约恢复、每日配额、模型数据脱敏、统一模型并发上限、超时/429/5xx 重试、鉴权错误不重试、已有画像续跑、报告质量、行动项编号格式、超长报告警告不致命、隐私删除、管理员填写记录与失败任务、管理员审计、语音接口、404 和移动端页面行为。

## 4. 修改问卷时

新增或修改字段时，至少同步检查：

1. 01-问卷与报告规范.md。
2. frontend/src/types/assessment.ts。
3. frontend/src/pages/AssessmentPage.tsx。
4. frontend/src/features/assessment/options.ts。
5. backend/app/schemas/assessment.py。
6. backend/app/services/assessment_validator.py。
7. backend/app/services/profile_prompt.py 和 report_prompt.py。
8. backend/app/storage/json_db.py 的持久化和数据边界。
9. 04-数据隐私与保留策略.md。
10. 对应测试和 06-版本更新记录.md。

## 5. 修改报告时

需要同时检查：

- 画像 schema 和画像 prompt。
- 报告 prompt 和质量检查。
- 前端 ReportRenderer 的章节解析。
- 管理员编辑和报告版本。
- 报告相关测试。

## 6. 数据库注意事项

当前表结构由应用启动时的 CREATE TABLE 语句维护，没有正式迁移工具。新增字段或索引时要兼容已有数据库；正式环境改表前必须备份并在测试数据库验证。

本次任务队列会自动补充 `generation_jobs` 的队列和租约索引，应用启动会自动执行兼容 SQL；上线前仍应先备份数据库，并确认失败任务保留和删除结果。

管理员页面相关入口集中在 `frontend/src/pages/Admin*.tsx` 和 `frontend/src/components/AdminNavigation.tsx`；任务错误和恢复逻辑集中在 `backend/app/services/generation_jobs.py`、`backend/app/api/admin.py`、`backend/app/api/assessments.py` 和 `backend/app/storage/json_db.py`。

## 7. 提交前检查

~~~bash
git diff --check
cd backend && python -m unittest discover -s tests
cd ../frontend && npm test && npm run typecheck && npm run build
~~~

功能更新完成后，在 06-版本更新记录.md 追加一条简短记录，只写日期、标题和更新内容。

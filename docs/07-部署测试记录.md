# Siyuan Compass（交小航）部署测试记录

本文档记录 Siyuan Compass 测试/预发布环境的部署验证、并发测试和问题定位结果。

后续测试只追加新的日期小节，不覆盖历史结果。文档中的服务器测试均限定在已授权的测试实例，不用于生产环境，不访问 `sjtu-production` 分支。

## 1. 测试边界和安全要求

- 授权测试实例：`i-bp187xpeswbp004en3gz`。
- 服务器测试环境：`/opt/SIYUAN-COMPASS`，当前分支为 `main`。
- 不访问生产环境、`sjtu-production` 分支或其他未授权服务器。
- 不执行代码修改、服务器配置修改、服务重启、Git 提交/推送或数据库结构修改。
- 不执行 `git reset --hard`、`git clean`、`docker compose down -v`、数据库卷删除、业务数据批量删除或数据库清空。
- 测试只使用合成账号和虚拟学生数据。
- 测试账号使用 `test` 前缀，学号使用 `TEST-` 前缀，邮箱使用 `example.invalid` 域名。
- 测试产生的账号、问卷、画像、任务和报告默认保留，除非用户明确要求清理。
- 文档只记录脱敏配置和统计信息，不记录 API Key、密码、Token、数据库密码、完整环境变量、完整问卷或模型请求/响应。

## 2. 测试方法和指标口径

### 2.1 执行流程

1. 只读确认服务器、分支、提交版本、镜像版本和部署配置。
2. 检查 Docker Compose/容器、PostgreSQL、后端健康接口、前端访问和反向代理。
3. 读取实际 API 路由、问卷 schema、任务状态和管理员监控接口。
4. 检查已有任务基线，确认没有遗留 `queued` 或 `running` 任务。
5. 使用完整、连贯的合成问卷，通过真实的 `POST /api/assessment-jobs` 提交任务。
6. 先执行串行冒烟测试；冒烟成功后再执行指定并发测试。
7. 持续轮询每个任务到 `success`、`failed` 或 `cancelled` 等明确终态。
8. 用管理员接口核对任务状态、阶段、模型请求、重试和质量修复统计。
9. 测试结束后复核健康状态、数据库连接和遗留任务数量。

### 2.2 时间和耗时口径

- 测试时间统一以 `Asia/Shanghai`（UTC+8）记录。
- 总耗时：从该账号提交线程开始到任务进入终态。
- 排队耗时：从接口返回接受到首次观察到 `running` 的时间。
- 阶段时间来自任务接口轮询，当前轮询间隔为 4 秒；短暂的 `report_validating`、`saving` 等阶段可能未被轮询正好捕获。
- “实际模型请求并发数”需要 provider 或模型接口提供 in-flight 指标；如果只能看到任务状态，则只报告任务级 `running` 数量，不猜测模型请求并发数。

### 2.3 结果判定

- 通过：任务可接受、可排队、可执行并进入明确终态，接口权限和数据隔离正确，且报告质量状态达到预期。
- 部分通过：核心链路完成，但出现质量告警、统计不可观测或部分非致命问题。
- 失败：出现任务无法接受、任务永久卡住、跨账号读取、数据库/服务不可用或批量任务异常失败。

## 6. 综合结论和后续建议

### 6.1 结论

本测试环境的账号登录、问卷提交、持久化队列、20 个任务级 Worker 并发、排队、画像生成、报告生成、重试、管理员监控、学生报告接口和跨账号隔离已在30、40、50和75并发轮次中验证。

本轮75并发总体结论为：**部分通过**。

- 通过项：75个任务全部受理，73个成功，服务无遗留任务，数据库和前端健康，权限隔离正确，任务级并发上限和队列生效。
- 待改进项：2个任务在报告质量修复后失败；73份成功报告中72份为 qualityStatus=warning，主要集中在模块超长、报告长度和行动项质量。
- 定位项：test035、test076 的错误码为 REPORT_MODEL_AUTH，但失败信息指向质量门禁失败，错误分类需要后续单独修复。
- 观测限制：当前没有 provider 级实时模型请求并发指标；成功重试的具体 429、5xx、超时原因未持久化。

### 6.2 建议

1. 优化报告提示词，使第三、第四模块稳定落在建议长度范围内。
2. 强化行动项编号格式，减少“行动项格式或数量异常”告警。
3. 继续降低模型输出中的绝对化或不建议表达。
4. 在管理员监控中增加 provider 请求 in-flight、429、5xx、超时和 `finish_reason` 分类统计。
5. 下一轮并发测试应继续使用新的合成学号，并明确测试账号是否复用；复用账号会增加其历史报告数量，但不应删除旧数据。

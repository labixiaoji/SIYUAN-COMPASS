# 思源 Compass 部署记录（2026-08-28）

本文记录思源 Compass 在上海交通大学 AI+教育教学平台的部署方式，供后续维护、排障和版本交接使用。
本文只记录技术配置，不包含真实密钥、数据库密码或个人账号信息。

## 1. 部署范围

- 对外地址：`https://ai4edu.sjtu.edu.cn/shengya/`（以学校最终分配地址为准）
- 维护仓库：<https://github.com/labixiaoji/SIYUAN-COMPASS>
- 部署分支：`sjtu-production`
- 业务基线：本仓库 `main` 分支的最新稳定版本
- 学校适配：本分支仅增加 jAccount、校内模型网关、`/shengya/` 子路径和部署模板。

本分支不修改问卷题目、问卷校验、画像 Prompt、报告 Prompt 和通用管理员业务逻辑。通用功能以
`main` 为准；学校工作人员维护的旧 fork 只用于历史差异核对，不作为当前部署来源。

## 2. 运行架构

```text
浏览器
  |-- /shengya/      -> 公网 Nginx -> 127.0.0.1:18121 静态前端
  |-- /shengya/api/  -> 公网 Nginx -> 127.0.0.1:18120 FastAPI
  |-- /auth/         -> ai4edu 门户的 jAccount 登录

FastAPI
  |-- PostgreSQL 16：127.0.0.1:5432 / siyuan_compass
  |-- 校内模型网关：由 DEEPSEEK_BASE_URL 或 AI_API_BASE 指定
```

服务资源：

| 项目 | 约定值 |
| --- | --- |
| systemd 服务 | `siyuan-compass.service` |
| 服务用户 | `siyuan-compass` |
| 应用目录 | `/opt/siyuan-compass` |
| 后端监听 | `127.0.0.1:18120` |
| 静态站监听 | `127.0.0.1:18121` |
| 应用配置 | `/etc/siyuan-compass.env`，权限 `0600` |
| 可选共享模型配置 | `/etc/course-ai.env` |
| 数据库 | `siyuan_compass` |

`deploy/nginx-siyuan-compass-public.conf` 需要放入现有 HTTPS 主站的 server 块中，不能单独替代
ai4edu 主站配置。`deploy/nginx-siyuan-compass-static.conf` 用于内部静态站。

## 3. jAccount 接入

### 3.1 认证来源

思源 Compass 不单独保存 jAccount 密码，也不保存 OAuth access token，而是复用同域门户完成登录后的
Flask 签名 session：

```text
/shengya/api/auth/jaccount/login
  -> /auth/jaccount/login
  -> jAccount OAuth
  -> /auth/jaccount/callback
  -> /shengya/api/auth/jaccount/callback
  -> 原请求页面
```

后端只读取 session 中的 jAccount 标识和显示名，在本项目 `users` 表创建或更新影子账号。生产环境
设置 `LOCAL_AUTH_ENABLED=false` 后，本地注册、密码登录和修改密码接口均关闭。

### 3.2 管理员角色来源

门户的 `is_admin` 标记不会自动赋予思源 Compass 管理员权限。思源 Compass 的管理员角色由本项目
数据库独立维护，管理员仍可填写问卷、查看自己的报告，同时可以进入管理后台。

授权或撤销 jAccount 管理员角色：

```bash
cd /opt/siyuan-compass/backend
.venv/bin/python scripts/manage_jaccount_admin.py add <jaccount> [<jaccount> ...]
.venv/bin/python scripts/manage_jaccount_admin.py remove <jaccount> [<jaccount> ...]
```

命令可以在账号首次登录前执行；首次登录会补充真实显示名并保留已授予角色。命令不会把本地开发账号
转换为 jAccount 账号。

## 4. DeepSeek 接入

生产环境示例：

```text
LLM_PROVIDER=deepseek
DEEPSEEK_BASE_URL=https://models.sjtu.edu.cn/api/v1
DEEPSEEK_MODEL=deepseek-chat
```

后端支持项目专用的 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，也支持共享
`/etc/course-ai.env` 中的 `AI_API_KEY`、`AI_API_BASE`、`AI_MODEL`。共享配置存在时，`AI_API_BASE`
和 `AI_MODEL` 会覆盖对应的 DeepSeek 地址和模型，密钥则作为 `DEEPSEEK_API_KEY` 的备用来源。

密钥不应写入项目目录、Git 历史或本文档。上线前应通过 `/shengya/api/llm/status` 确认供应商、模型和
配置状态。

## 5. 服务器文件

| 文件 | 用途 |
| --- | --- |
| `/etc/systemd/system/siyuan-compass.service` | FastAPI 服务定义 |
| `/etc/siyuan-compass.env` | 数据库、认证和站点配置，权限 `0600` |
| `/etc/nginx/snippets/siyuan-compass-location.conf` | ai4edu 主站 `/shengya/` 路由 |
| `/etc/nginx/conf.d/siyuan-compass-static.conf` | 内部静态站 `18121` |
| `/opt/siyuan-compass/backend/.venv` | 生产 Python 环境 |
| `/opt/siyuan-compass/frontend/dist` | `/shengya/` 前端构建产物 |

仓库中的对应模板全部位于 `deploy/`，模板不包含真实密码和密钥。

## 6. 前端构建

必须带子路径和生产认证开关构建：

```bash
cd /opt/siyuan-compass/frontend
VITE_BASE_PATH=/shengya/ \
VITE_API_BASE_URL=/shengya/api \
VITE_ENABLE_LOCAL_AUTH=false \
npm run build
```

构建后检查 `frontend/dist/index.html`，脚本和样式地址应以 `/shengya/assets/` 开头；
`/shengya/assessment` 等 SPA 直达路由应正常返回前端入口。

## 7. 更新流程

产品开发和部署适配分开维护。更新部署分支时，先同步自己的 `main`，再把 `main` 合入
`sjtu-production`，不要把旧 `school-legacy/sjtu-production` 整体覆盖过来：

```bash
git fetch origin
git switch main
git pull --ff-only origin main
git switch sjtu-production
git pull --ff-only origin sjtu-production
git merge main
```

首次安装或后端依赖变化时：

```bash
cd /opt/siyuan-compass/backend
python3 -m venv .venv                         # 仅首次执行
.venv/bin/pip install -r requirements.txt
```

发布前备份数据库、`/etc/siyuan-compass.env` 和当前前端产物。不要覆盖服务器环境变量，也不要使用
会删除服务器额外文件的 `rsync --delete`。

安装或更新 systemd 模板后执行：

```bash
systemctl daemon-reload
systemctl enable --now siyuan-compass
systemctl restart siyuan-compass
systemctl status siyuan-compass --no-pager
journalctl -u siyuan-compass -n 100 --no-pager
```

只有 Nginx 配置发生变化时才执行 `nginx -t`，确认成功后再 reload；检查失败时不要 reload。

本地发布前执行：

```bash
cd backend
python -m unittest discover -s tests

cd ../frontend
npm test -- --run
npm run typecheck
VITE_BASE_PATH=/shengya/ \
VITE_API_BASE_URL=/shengya/api \
VITE_ENABLE_LOCAL_AUTH=false \

```

服务器上确认：

- `siyuan-compass.service` 为 `active`；
- `/shengya/` 和 `/shengya/assets/...` 返回 200；
- `/shengya` 跳转到 `/shengya/`；
- `127.0.0.1:18120/health` 返回 `{"status":"ok"}`；
- `/shengya/api/llm/status` 显示校内 DeepSeek 配置；
- jAccount 登录后能回到 `/shengya/assessment`；
- 正式登录页不显示本地注册和密码登录；
- PostgreSQL 表已初始化且账号具备必要权限。

## 9. 回退原则

1. 发布前记录 `sjtu-production` 的提交 SHA。
2. 代码异常时切换到上一个已验证提交，重新构建前端并重启服务。
3. 配置变更前备份 `/etc/siyuan-compass.env` 和 Nginx 配置。
4. 数据库结构变更前先完成 PostgreSQL 备份。
5. 回退时不要删除服务器上的环境变量、数据库和其他应用文件。

## 10. 当前边界

- 报告任务执行器仍运行在 FastAPI 进程内；任务输入、状态和租约保存在 PostgreSQL，服务重启后可按租约恢复。
- 当前学校模板按单后端进程设计，扩大使用范围前仍需压测校内模型网关和数据库。
- jAccount 适配依赖门户与生涯助手同域部署；迁移到独立域名或服务器时，不能直接复制门户 session 密钥。
- 本分支不包含旧部署版本中临时关闭问卷、并发护航和模型传输层的运营性提交；如需恢复，应单独评估并记录。
- 通用业务功能以后续 `main` 为准，学校适配只保留认证、模型和部署差异。
